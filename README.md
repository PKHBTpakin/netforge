# NetForge — Network Planning Suite

[![tests](https://github.com/PKHBTpakin/netforge/actions/workflows/tests.yml/badge.svg)](https://github.com/PKHBTpakin/netforge/actions/workflows/tests.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

เครื่องมือวางแผนเครือข่าย คำนวณ VLSM (IPv4) และการแบ่ง Subnet แบบ IPv6 พร้อมจำลอง Topology
บน Canvas และสร้างคำสั่ง Cisco IOS ให้อัตโนมัติ ทำงานทั้งหมดในเบราว์เซอร์ ไม่ต้องติดตั้งอะไร

**เปิดใช้งานจริงได้ที่** https://pkhbtpakin.github.io/netforge/

---

## เริ่มใช้งาน

เปิด `index.html` ด้วยเบราว์เซอร์ได้เลย ไม่ต้อง build ไม่ต้อง `npm install`

> **แนะนำให้เปิดผ่าน http แทนการดับเบิลคลิกไฟล์** — ดูหัวข้อ [ทำไมไม่ควรเปิดด้วย file://](#ทำไมไม่ควรเปิดด้วย-file)

วิธีเปิดผ่าน http แบบเร็วที่สุด (เลือกอย่างใดอย่างหนึ่ง)

```bash
python -m http.server 8000     # แล้วเปิด http://localhost:8000
npx serve .                    # หรือ
```

| **CLI Generator** | สร้าง config Cisco IOS แยก Router / Switch รองรับ Dual-Stack และกัน Static IP ออกจาก DHCP Pool |

## การเก็บข้อมูล — ไม่ต้อง login

ข้อมูลทั้งหมดอยู่ในเครื่องผู้ใช้เท่านั้น ไม่มีเซิร์ฟเวอร์ ไม่มีบัญชีผู้ใช้ ไม่มีการส่งข้อมูลออกไปไหน

| วิธี | เก็บที่ไหน | ข้ามเครื่องได้ | ใช้เมื่อ |
|---|---|---|---|
| **Autosave** | `localStorage` (ช่องเดียว เขียนทับตลอด) | ไม่ | กันรีเฟรชแล้วข้อมูลหาย |
| **คลังโปรเจกต์** | `localStorage` (สูงสุด 50 ชิ้น) | ไม่ | เก็บงานหลายเวอร์ชันไว้เปิดทีหลัง |
| **ลิงก์แชร์** | อยู่ในตัว URL เอง | **ได้** | ส่งงานให้คนอื่น / นำเสนอ |
| **ไฟล์ `.json`** | เครื่องผู้ใช้ | **ได้** | สำรองระยะยาว ส่งไฟล์แนบ |

**รูปแปลนอาคารเป็นข้อยกเว้นเดียว** — รูปถูกย่อเหลือด้านยาวสุด 1,600 px และเข้ารหัสใหม่เป็น JPEG
ตั้งแต่ตอนนำเข้า ได้ไฟล์ราว 120–350 KB ซึ่งยังเก็บลง `localStorage` และไฟล์ `.json` ได้
แต่ **ไม่ติดไปกับลิงก์แชร์** เพราะจะทำให้ URL ยาวเกินเพดานทันที (ทั้งโปรเจกต์ที่เหลือรวมกันราว 2 KB)
ถ้าต้องการส่งรูปไปด้วย ให้ใช้ปุ่ม **SAVE** ส่งเป็นไฟล์ `.json` แทน

ขนาดจริงของโปรเจกต์ใหญ่สุดที่รองรับ (12 แผนก + อุปกรณ์และลิงก์บนผัง) อยู่ที่ **~2 KB**
โควตา `localStorage` ปกติ 5 MB จึงเก็บได้ราว **2,700 โปรเจกต์** — พื้นที่ไม่ใช่ข้อจำกัด

**จะต้องมี login เมื่อไหร่?** เฉพาะกรณีที่ต้องการให้เปิดงานเดิมได้จากทุกเครื่อง หรือให้ผู้สอน
เก็บงานผู้เรียนรวมศูนย์ ซึ่งต้องมี backend + ฐานข้อมูล ตอนนี้ยังไม่มีและยังไม่จำเป็น
ลิงก์แชร์ครอบคลุมกรณี "ส่งงานให้คนอื่นดู" ได้แล้วโดยไม่ต้องมีบัญชี

## ทำไมไม่ควรเปิดด้วย `file://`

พฤติกรรมของที่เก็บข้อมูลบนโปรโตคอล `file://` **ไม่ได้ถูกกำหนดไว้ในมาตรฐาน** และต่างกันไปตามเบราว์เซอร์
Safari โยน `SecurityError`, Firefox มีประวัติบั๊กที่ `localStorage` ไม่ทำงาน, ส่วน IndexedDB มัก
ถูกบล็อกเพราะเบราว์เซอร์ถือว่าแต่ละไฟล์เป็นคนละ origin

โค้ดห่อ `try/catch` ไว้ทุกจุดจึงไม่พัง แต่ผลคือ **Autosave กับคลังโปรเจกต์อาจไม่ทำงานเงียบ ๆ**
(แอปจะขึ้นข้อความแจ้งให้ใช้ไฟล์ `.json` แทน) นอกจากนี้ลิงก์แชร์ที่สร้างจาก `file://` ก็ใช้ได้
เฉพาะบนเครื่องที่มีไฟล์นั้นอยู่จริง ส่งให้คนอื่นไม่ได้

## นำขึ้น GitHub Pages (ฟรี ใช้เวลาไม่ถึง 5 นาที)

ได้ origin แบบ `https://` จริง ทำให้ที่เก็บข้อมูลทำงานเสถียรทุกเบราว์เซอร์ และเวลานำเสนอ
แค่เปิดลิงก์ ไม่ต้องหอบโฟลเดอร์ไปด้วย

```bash
# 1. สร้าง repository ใหม่บน github.com (ตั้งเป็น Public) ชื่อ netforge

# 2. ในโฟลเดอร์โปรเจกต์นี้
  git remote add origin https://github.com/<ชื่อผู้ใช้ของคุณ>/netforge.git
git branch -M main
git push -u origin main

# 3. บน GitHub: Settings -> Pages
#    Source: Deploy from a branch
#    Branch: main  /  โฟลเดอร์: / (root)  -> Save

# 4. รอ 1-2 นาที แล้วเปิด
#    https://<ชื่อผู้ใช้ของคุณ>.github.io/netforge/
```

ไฟล์ `.nojekyll` ในโปรเจกต์มีไว้บอก GitHub Pages ว่าไม่ต้องประมวลผลด้วย Jekyll
(ถ้าไม่มี ไฟล์หรือโฟลเดอร์ที่ขึ้นต้นด้วย `_` จะถูกข้ามไป)

## Router สาขาและลิงก์ WAN

> **อ่านก่อน — จุดที่คนสะดุดกันทุกคน**
> Router หลัก (`Router-01`) มีมาให้ตัวเดียวตั้งแต่ต้นและลบไม่ได้
> ปุ่ม **Router** บน Canvas วาง **Router สาขา** เสมอ ไม่ได้วาง Router อิสระตัวที่สอง
> และ Router สาขา **ยังใช้งานไม่ได้จนกว่าจะลากลิงก์ WAN ไปหา Router ตัวอื่นก่อน** —
> ก่อนเชื่อม มันจะไม่มี IP ฝั่ง WAN ไม่มี default route และถ้าเผลอลากไปคุมแผนกไว้แล้ว
> แผนกนั้นจะถูกตัดขาดจากเครือข่ายส่วนอื่นทันที
> แอปจะขึ้นกรอบสีเหลืองพร้อมเครื่องหมาย `!` บน Router ที่ยังลอยอยู่ และบอกวิธีแก้ในแผงรายละเอียด

### ทำตามลำดับนี้

1. กดปุ่ม **Router** มุมขวาบนของ Canvas แล้วคลิกวางตำแหน่ง
2. **กด Connect ลากจาก Router สาขาไปหา Router-01 ก่อนเป็นอย่างแรก** — ระบบจอง `/30` จาก WAN Pool
   ให้ทันที และกรอบเหลืองจะหายไป (ข้อนี้ห้ามข้าม)
3. ลาก Router สาขาไปเชื่อมกับ Switch ของแผนกใด แผนกนั้นจะย้ายไปอยู่หลังสาขานั้น
   และสายจาก Router หลักจะถูกตัดออกเองอัตโนมัติ
4. แท็บ **CLI Config** จะมีปุ่มเลือกดู config ทีละ Router
5. คลิก Router สาขาเพื่อแก้ชื่อ ดูลิงก์ WAN ลบสายทีละเส้น หรือลบทั้งตัว

### อยากเห็นของจริงก่อน

กด **EXAMPLE** แล้วเลือกชุดที่มีป้ายจำนวนสาขา — ผังจะถูกต่อมาให้ครบตั้งแต่โหลด

| ชุด | ได้อะไร |
|---|---|
| **สำนักงานใหญ่ กับ 2 สาขา** | HQ 3 แผนก + สาขาเชียงใหม่ (2 แผนก) + สาขาขอนแก่น (1 แผนก) |
| **บริษัท 3 สาขา ผังครบ** | HQ 3 แผนก + สาขาเหนือ/ใต้/ตะวันออก รวม 5 แผนก |
| **ร้านค้าปลีก สำนักงานใหญ่ + 3 สาขา** | HQ 4 แผนก + หน้าร้าน 3 สาขา สาขาละ 2 แผนก (จุดขาย + หลังร้าน) ทุกสาขาขนาดเท่ากัน |

### ขยายได้ถึงกี่สาขาจริง ๆ

ชุดร้านค้าปลีกออกแบบให้ทุกสาขาเหมือนกันเป๊ะ เพื่อใช้ตอบคำถามว่า "ถ้ามี 350 สาขาจะทำยังไง"
ตัวเลขข้างล่างมาจากการทดลองสร้าง 350 สาขาจริงบน v2.8 ไม่ใช่การประมาณ

| เรื่อง | ผลที่วัดได้ |
|---|---|
| WAN Pool ค่าเริ่มต้น `10.255.255.0/24` | จองได้ **64 ลิงก์** ต้องขยายเป็น `/21` ถึงจะครบ 350 |
| WAN Pool `/21` | จองครบ **350 ลิงก์** ไม่มีข้อผิดพลาด |
| ชื่อพอร์ตที่สร้างให้ | ไล่ไปถึง `Serial0/349/0` ซึ่ง**ไม่มีอยู่จริงบน Router รุ่นใด** (2911 + HWIC-2T มี 2–4 พอร์ต) |
| config ของ Router หลัก | **2,855 บรรทัด (89 KB)** วางลง Packet Tracer ไม่ไหว |
| ผัง | Router ทั้ง 350 ตัวถูกวางทับกันที่จุดเดียว ผังกว้าง **0 px** |
| ความเร็ว | สร้าง 2 ms / สร้าง config 19 ms — **ไม่ใช่คอขวด** |

**เพดานที่แท้จริงคือ 11 สาขา ไม่ใช่ 350** เพราะ `MAX_DEPARTMENTS = 12` และสาขาต้องมีอย่างน้อย
1 แผนกอยู่ข้างหลังจึงจะมีวงเครือข่ายให้ HQ สร้างเส้นทางไปหา สาขาที่ไม่มีแผนกคือกล่องเปล่า
ที่มีแค่ลิงก์ WAN — มีเทส `E25` คุมข้อนี้ไว้

ถ้าต้องนำเสนอกรณีหลายร้อยสาขา ให้สาธิตด้วยสาขาตัวแทน 3 สาขา แล้วอธิบายแผนการแบ่งช่วง
ที่ขยายไปถึง 350 ได้ด้วยการคำนวณ ซึ่งตรงกับที่ทำกันในงานจริงอยู่แล้ว ไม่มีใครวาดครบ 350 สาขา

## โหมดฝึกทำโจทย์

ส่วนอื่นของโปรแกรมทำงานแทนผู้ใช้ทั้งหมด ซึ่งดีเวลาต้องการผลลัพธ์เร็ว แต่ถ้าเป้าหมายคือ *เข้าใจ*
การได้คำตอบมาเลยกลับไม่ช่วย เพราะไม่ได้ผ่านขั้นตอนคิดด้วยตัวเอง แท็บนี้จึงกลับทิศทาง

| ขั้นตอน | เกิดอะไรขึ้น |
|---|---|
| กดเริ่มทำโจทย์ | โปรแกรมสุ่มช่วง IP ตั้งต้นและรายชื่อแผนกพร้อมจำนวนเครื่องให้ |
| กรอกคำตอบ | ต้องหา Network, ขนาด, เบอร์แรกที่ใช้ได้, เบอร์สุดท้ายที่ใช้ได้ และ Broadcast ของทุกแผนกเอง |
| กดตรวจ | ตรวจ**ทีละช่อง** ช่องที่ถูกขึ้นขอบเขียว ช่องที่ผิดขึ้นขอบแดง |
| ถ้าผิด | บอกว่าพลาดที่ขั้นไหน เช่น *"ขนาดที่ให้เล็กเกินไป แผนกนี้ขอ 38 เครื่อง ต้องบวกอีก 2 เบอร์ รวมเป็น 40 แล้วปัดขึ้นเป็นกำลังสองได้ 64 ซึ่งตรงกับ /26"* |
| กดดูเฉลย | แสดงวิธีคิดทีละขั้นเรียงตามลำดับที่จัดสรรจริง ไม่ใช่แค่โชว์คำตอบ |

ระดับความยากมี 3 ระดับ คือ 3 แผนกบน `/24`, 5 แผนกบน `/23` และ 7 แผนกบน `/22`

**จุดออกแบบที่สำคัญที่สุด:** เฉลยมาจาก `solveVLSM()` ใน `js/vlsm.js` ซึ่งเป็นฟังก์ชันตัวเดียว
กับที่ใช้คำนวณงานจริง ไม่ได้เขียนโค้ดเฉลยขึ้นมาใหม่ จึงไม่มีทางที่เฉลยจะไม่ตรงกับสิ่งที่โปรแกรมทำจริง
ถ้าวันหนึ่งแก้เครื่องคำนวณ เฉลยจะเปลี่ยนตามเองอัตโนมัติ — มีเทสคุมข้อนี้ไว้โดยเฉพาะ

โจทย์ที่สุ่มได้ทุกข้อถูกตรวจซ้ำก่อนส่งออกว่า**จัดสรรได้ครบทุกแผนกจริง** ผู้ใช้จึงไม่มีทางเจอโจทย์ที่ไม่มีคำตอบ

### สัญญาณนาฬิกาของสายอนุกรม (`clock rate`)

สายอนุกรมแบบเชื่อมตรงสองจุดต้องมีฝั่งหนึ่งเป็นคนจ่ายสัญญาณนาฬิกา เรียกว่าฝั่ง **DCE**
ซึ่งเป็นฝั่งเดียวที่ต้องมีคำสั่ง `clock rate` ในคอนฟิก **ถ้าฝั่งนั้นไม่ได้ตั้ง สายจะไม่ขึ้นเลย**
ทั้งที่ IP ถูกหมดแล้ว และไม่มี error อะไรขึ้นมาบอก

**ข้อจำกัดเชิงข้อมูล:** "ฝั่งไหนเป็น DCE" คำนวณจากผังไม่ได้ เพราะขึ้นกับว่าปลายสายด้านไหน
ถูกเสียบเข้ากับอุปกรณ์ตัวไหน ซึ่งเป็นเรื่องของสายจริง ไม่ใช่ตรรกะของเครือข่าย
(ในงานจริงที่เช่าสายจากผู้ให้บริการ ตัวจ่ายนาฬิกาคืออุปกรณ์ของผู้ให้บริการ ทั้งสอง Router
เป็น DTE ทั้งคู่ และไม่ต้องตั้ง `clock rate` เลย)

โปรแกรมจึงจัดการแบบนี้

| เรื่อง | พฤติกรรม |
|---|---|
| ค่าเริ่มต้น | ให้ Router หลักเป็นฝั่ง DCE ตามธรรมเนียมที่ใช้กันในห้องแล็บ |
| ถ้าเสียบสายกลับด้าน | กดปุ่มสลับที่คอลัมน์สุดท้ายของตาราง WAN คำสั่งจะย้ายไปอีกฝั่งทันที |
| ฝั่งที่ไม่ใช่ DCE | ใส่คอมเมนต์อธิบายไว้ว่าทำไมถึงไม่มีบรรทัดนี้ และบอกวิธีสลับ |
| ความเร็ว | เลือกได้จากรายการค่าที่ IOS รับจริง ค่าเริ่มต้น 64,000 |
| การบันทึก | ฝั่ง DCE ที่เลือกเองถูกเก็บลงไฟล์ `.json` และคลังโปรเจกต์ด้วย |

จงใจ**ไม่**ใส่ `clock rate` ให้ทั้งสองฝั่ง ถึงแม้อุปกรณ์จะรับไว้แล้วไม่ทำอะไรถ้าฝั่งนั้นเป็น DTE
เพราะจะทำให้คนที่ใช้เรียนเข้าใจผิดว่าต้องใส่ทั้งคู่

### ต่อได้กี่ตัว ต่อแบบไหน

วาง Router สาขาได้ไม่จำกัด แต่ควรต่อ **แบบดาว** คือทุกสาขาต่อตรงเข้า Router หลัก
ทราฟฟิกระหว่างสาขาจะวิ่งผ่าน HQ ซึ่งถูกต้องตามผังแบบนี้

**ยังไม่รองรับการต่อเป็นลูกโซ่** (HQ → A → B) เพราะระบบสร้าง static route ให้เฉพาะเพื่อนบ้าน
ที่ต่อตรงกันเท่านั้น ไม่ได้ไล่เส้นทางต่อทอด ถ้าต่อเป็นลูกโซ่ HQ จะไม่มีเส้นทางไปหาแผนกที่อยู่หลัง B
ตัวอย่างที่ให้มาจึงเป็นแบบดาวทั้งหมดโดยตั้งใจ

## รูปแปลนอาคารใต้ผัง

วางแปลนอาคารเป็นฉากหลัง แล้วลากอุปกรณ์ไปวางตรงตำแหน่งจริงในตึกได้ ทำให้ผังตอบคำถามเพิ่มอีกข้อ
ที่ผังลอย ๆ ตอบไม่ได้: *"Switch ตัวนี้ต้องไปติดตั้งตรงไหน"*

1. กดปุ่ม **แปลน** มุมขวาบนของ Canvas → เลือกรูป `PNG` / `JPG` / `WebP`
2. รูปจะถูกย่อและเข้ารหัสใหม่อัตโนมัติ แล้วเข้าโหมด **ลากรูปได้** ทันที — ลากเพื่อจัดตำแหน่ง
3. ปรับ **ความจาง** และ **ขนาด** ด้วยแถบเลื่อนให้พอดีกับผัง
4. กด **ล็อก** เมื่อจัดเสร็จ — สำคัญมาก เพราะตอนปลดล็อกอยู่ การลากพื้นที่ว่างจะไปโดนรูปแทนการเลื่อนผัง

| เรื่อง | พฤติกรรม |
|---|---|
| ขนาดหลังย่อ | ด้านยาวสุดไม่เกิน 1,600 px เข้ารหัสเป็น JPEG คุณภาพ 0.72 → ราว 120–350 KB |
| บันทึกลงไฟล์ `.json` | **ติดไป** |
| บันทึกลงคลัง / Autosave | **ติดไป** (ถ้า `localStorage` เต็มจะขึ้นเตือนให้ใช้ไฟล์ `.json` แทน) |
| ลิงก์แชร์ | **ไม่ติดไป** — ใหญ่เกินใส่ใน URL แอปจะแจ้งเตือนทุกครั้งที่คัดลอกลิงก์ |
| Export PNG | **ติดไป** และกรอบภาพจะขยายให้ครอบแปลนทั้งใบ ไม่ตัดเหลือแค่ส่วนที่มีอุปกรณ์ |
| `Ctrl+Z` | ย้อนได้ทั้งการใส่รูปและการลบรูป |

### มุมมองผัง

พอมีอุปกรณ์เยอะ ผังจะกว้างเกินกรอบ ใช้แถบควบคุมมุมล่างขวาหรือวิธีลัดเหล่านี้

| ทำอะไร | วิธี |
|---|---|
| ย่อ / ขยาย | หมุนล้อเมาส์ (ซูมเข้าหาตำแหน่งเคอร์เซอร์) หรือกดปุ่ม `+` `−` |
| เลื่อนผัง | ลากพื้นที่ว่างบน Canvas |
| เห็นทุกอุปกรณ์พอดีกรอบ | ปุ่ม ⛶ |
| กลับ 100% | ปุ่ม ↺ |

สิ่งที่ระบบสร้างให้เอง

| ฝั่ง | ได้อะไร |
|---|---|
| สำนักงานใหญ่ | interface WAN + **static route** เจาะจงไปยังทุกวงที่อยู่หลังสาขา |
| สาขา | interface WAN + sub-interface ของแผนกตัวเอง + DHCP pool เฉพาะของตัวเอง + **default route** กลับต้นทาง |

ใช้ `/30` เพราะให้ usable address พอดี 2 ตัว ตรงกับลิงก์ point-to-point
สาขาที่มีทางออกทางเดียว (stub network) ใช้ default route ตามมาตรฐานปฏิบัติ ไม่ต้องไล่ static ทีละวง

## ข้อจำกัดที่รู้อยู่

- จำกัด 12 แผนกต่อโปรเจกต์ (เท่ากับจำนวนสีในชุด เพื่อไม่ให้มีแผนกไหนได้สีซ้ำกัน)
- CLI ใช้ชื่อ interface คงที่ (`Gi0/0`, `Gi0/1`, `Fa0/2`+, `Se0/n/0`) และ DNS `8.8.8.8`
- ชื่อแผนก/สาขาที่มีเว้นวรรคหรือภาษาไทย จะถูกแปลงเป็นชื่อ ASCII คำเดียวเฉพาะตอนใช้เป็น
  `hostname` กับ `ip dhcp pool` (IOS รับได้แค่นั้น) ชื่อที่ตัดจนเหลือค่าว่างจะใช้ `DEPT-<id>` แทน
  โดยมีคอมเมนต์กำกับชื่อจริงไว้เหนือคำสั่งเสมอ ส่วน `description` และแท็บบนหน้าจอยังใช้ชื่อเดิม
- `enable secret` ในทุก config ตั้งเป็น `cisco` สำหรับใช้ในห้องแล็บ มีคอมเมนต์เตือนกำกับไว้แล้ว
  แต่ยังไม่มีช่องให้ตั้งรหัสเอง — ต้องแก้ในไฟล์ที่ export ออกไป
- ลิงก์ WAN ใช้ static route / default route เท่านั้น ยังไม่รองรับ routing protocol (OSPF, EIGRP)
- **ต่อ Router ได้เฉพาะแบบดาว** (ทุกสาขาต่อตรงเข้า Router หลัก) ยังต่อเป็นลูกโซ่ไม่ได้ เพราะ
  `getStaticRoutesForRouter()` สร้างเส้นทางให้เฉพาะเพื่อนบ้านที่ต่อตรงกัน ไม่ได้ไล่ต่อทอด
- ยังไม่รองรับลิงก์สำรอง (redundancy) หรือ HSRP
- รูปแปลนอาคารไม่ติดไปกับลิงก์แชร์ (ใหญ่เกินใส่ใน URL) และยังหมุน/บิดรูปไม่ได้ ปรับได้แค่
  ตำแหน่ง ขนาด และความจาง
- โหลด Google Fonts และ Font Awesome จาก CDN — ต้องต่ออินเทอร์เน็ตตอนเปิดครั้งแรก และยังไม่ได้ใส่ SRI
  (เหตุผลรายตัวอยู่ในคอมเมนต์เหนือแท็กทั้งสองใน `index.html`) ส่วน Tailwind ไม่พึ่ง CDN แล้ว
- CSP ประกาศไว้แล้วแต่ยังต้องเปิด `'unsafe-inline'` ให้ script เพราะ UI ใช้ `onclick=` 68 จุด
  จึงยังไม่ใช่ตาข่ายกัน XSS ในตัวมันเอง ด่านแรกยังเป็น `escapeHtml()` เหมือนเดิม
- pinch zoom สองนิ้วบนมือถือยังเป็นการซูมทั้งหน้าเว็บ ไม่ใช่ซูมเฉพาะผัง
- `js/ui.js` ยาว 1,296 บรรทัด (ลดจาก 1,569 หลังแยก `cli.js` ออก) ยังทำหลายหน้าที่อยู่
  ก้อนถัดไปที่ควรผ่าคือ layout/resizer
- สคริปต์ทุกไฟล์แชร์ global scope เดียวกันและ **ลำดับใน `index.html` ห้ามสลับ** — ยังไม่ได้ย้ายไป ES Modules
- `aria-label` ใส่ครบแล้วเฉพาะปุ่มที่มีแต่ไอคอน ส่วนการใช้งานด้วยคีย์บอร์ดล้วนบน Canvas ยังทำไม่ได้
