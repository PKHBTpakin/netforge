# ตารางเทียบคำในแอป ก่อนและหลังแก้

เอกสารนี้ทำไว้ให้ตรวจทานด้วยตาเอง ไม่ใช่ให้เชื่อตามทันที
อ่านทีละบรรทัดแล้วแก้ตรงไหนที่รู้สึกว่าไม่ใช่สำนวนตัวเองได้เลย เพราะคนที่ต้องไปนำเสนอคือเรา

---

## หลักที่ใช้ตัดสินว่าอะไรควรแก้

1. **เลิกใช้ขีดยาว `—` คั่นกลางประโยค** — ของเดิมมี 84 จุดในโค้ด ทำให้อ่านสะดุด และเป็นสัญญาณที่คนอ่านออกว่าเขียนโดย AI
2. **เลิกใช้จุดกลาง `·` คั่นรายการ** ให้ขึ้นบรรทัดใหม่หรือใช้คำว่า "และ" แทน
3. **ข้อความภาษาอังกฤษล้วนในแอปภาษาไทย** เช่น `VLSM Calculated` `Layout reset` แปลเป็นไทยให้หมด
4. **ข้อความสั้นห้วนแบบโน้ตย่อ** เช่น `Hosts >= 1` เขียนเป็นประโยคที่อ่านแล้วรู้ว่าต้องทำอะไรต่อ
5. **ศัพท์เทคนิคของวิชาคงไว้** VLSM, Subnet, Router, DHCP, Switch ไม่แปล
   แต่ศัพท์ที่คนนอกวงไม่รู้จักให้อธิบายสั้น ๆ ครั้งแรกที่โผล่ เช่น "Base (ช่วง IP ตั้งต้น)"

## หน้าคู่มือ แท็บ "เริ่มต้น"

| เดิม | ใหม่ |
|---|---|
| *(ไม่มี)* | เพิ่มหัวข้อ **"โปรแกรมนี้ทำอะไร"** ไว้บนสุด อธิบายภาพรวมก่อนเข้าขั้นตอน |
| **2. ปุ่มไม้กายสิทธิ์ ข้าง Calculate**<br>หา Base ที่พอดีที่สุดให้อัตโนมัติ — ลดพื้นที่เหลือทิ้งได้มาก | **2. ให้โปรแกรมเลือกเลขตั้งต้นให้**<br>เลข Base คือช่วง IP ตั้งต้นที่จะเอามาแบ่งให้ทุกแผนก ถ้าไม่รู้ว่าควรใส่เท่าไร ให้กดปุ่มรูปไม้กายสิทธิ์ที่อยู่ข้างปุ่ม Calculate |
| **3. อ่านแผงสรุปใต้ตาราง**<br>แยกให้เห็น ใช้จริง / เสียจากการปัด / สำรองเผื่อโต | **3. ดูว่าใช้ IP ไปคุ้มไหม**<br>แผงสรุปใต้ตารางจะบอกว่า IP ที่มีอยู่ถูกใช้ไปกับอะไรบ้าง แบ่งเป็นสามส่วนคือ ใช้งานจริง, ส่วนที่เสียไปเพราะต้องปัดขนาดขึ้น และส่วนที่ยังว่างไว้เผื่อขยายในอนาคต |
| **4. จัดผังบน Canvas**<br>ลากอุปกรณ์ได้อิสระ วาง PC/Server เพิ่มเอง คลิกโหนดเพื่อแก้รายละเอียด<br>ล้อเมาส์ = ย่อ/ขยาย · ลากที่ว่าง = เลื่อนผัง · ปุ่ม ⛶ = เห็นครบพอดีกรอบ | **4. จัดผังเครือข่าย**<br>ผังตรงกลางลากย้ายตำแหน่งได้ทุกชิ้น คลิกที่อุปกรณ์ตัวไหนก็ได้เพื่อดูหรือแก้รายละเอียดของตัวนั้น<br>หมุนล้อเมาส์เพื่อย่อขยาย ลากพื้นที่ว่างเพื่อเลื่อนผัง และกดปุ่มขยายเต็มกรอบเพื่อให้เห็นทุกอย่างพอดีหน้าจอ |
| **6. แท็บล่างมี 3 อย่าง**<br>IP TABLE ผลคำนวณ · CLI CONFIG คำสั่ง Cisco พร้อมคัดลอก · NET TOOLS Wildcard Mask และ Route Summary | **6. ดูผลลัพธ์ที่แท็บด้านล่าง**<br>IP TABLE คือตารางสรุปว่าแต่ละแผนกได้ IP ช่วงไหน<br>CLI CONFIG คือคำสั่งสำหรับตั้งค่าอุปกรณ์ Cisco คัดลอกไปวางบนอุปกรณ์ได้เลย<br>NET TOOLS เป็นเครื่องมือเสริมสำหรับหา Wildcard Mask และรวมเส้นทางหลายเส้นให้เหลือเส้นเดียว |

**คำที่เปลี่ยน:** โหนด → อุปกรณ์ · Canvas → ผัง · ปุ่ม ⛶ → ปุ่มขยายเต็มกรอบ

## หน้าคู่มือ แท็บ "หลายสาขา"

| เดิม | ใหม่ |
|---|---|
| **อ่านก่อน: Router ที่วางได้คือ "สาขา" เท่านั้น**<br>Router หลัก (Router-01) มีมาให้ตัวเดียวตั้งแต่ต้นและลบไม่ได้ ปุ่ม Router บน Canvas จะวาง Router สาขา เสมอ ซึ่งยังใช้งานไม่ได้จนกว่าจะลากลิงก์ WAN ไปหา Router ตัวอื่นก่อน | **อ่านตรงนี้ก่อน**<br>ในผังจะมี Router หลักชื่อ Router-01 ให้มาตั้งแต่แรกหนึ่งตัว และลบทิ้งไม่ได้ ส่วนปุ่ม Router ที่มุมขวาบน จะเป็นการเพิ่ม Router ของสาขาเสมอ<br><br>Router สาขาที่เพิ่งวางลงไปจะยังใช้งานไม่ได้ ต้องลากสายไปเชื่อมกับ Router ตัวอื่นก่อน ถ้าลืมขั้นตอนนี้ สาขานั้นจะไม่มีเลข IP และแผนกที่ย้ายไปอยู่กับมันจะติดต่อกับที่อื่นไม่ได้เลย |
| **2. เชื่อมเป็นลิงก์ WAN (ห้ามข้าม)**<br>กด Connect แล้วคลิก Router สองตัว — ระบบจอง /30 ให้อัตโนมัติ | **2. ลากสายไปเชื่อมกับ Router-01 (ห้ามข้ามขั้นตอนนี้)**<br>กดปุ่ม Connect แล้วคลิกที่ Router สองตัวที่ต้องการเชื่อมกัน<br>โปรแกรมจะแบ่งเลข IP สำหรับสายเส้นนี้ให้เองโดยใช้ขนาด /30 ซึ่งเป็นขนาดที่พอดีกับการเชื่อมสองจุด |
| **4. config แยกต่อ Router**<br>สำนักงานใหญ่ได้ static route ไปแต่ละสาขา · สาขาได้ default route กลับต้นทาง | **4. ดูคำสั่งของ Router แต่ละตัว**<br>สำนักงานใหญ่จะได้เส้นทางที่ระบุชัดเจนว่าจะไปหาแต่ละสาขาทางไหน ส่วนสาขาจะได้เส้นทางแบบส่งกลับมาที่สำนักงานใหญ่ทางเดียว เพราะสาขามีทางออกอยู่ทางเดียวอยู่แล้ว |
| **ต่อได้กี่ตัว ต่อแบบไหนได้บ้าง**<br>ควรต่อแบบดาว … ยังไม่รองรับการต่อเป็นลูกโซ่ (HQ→A→B) เพราะระบบสร้าง static route ให้เฉพาะเพื่อนบ้านที่ต่อตรงกัน | **ข้อควรรู้เรื่องรูปแบบการต่อ**<br>ควรต่อแบบให้ทุกสาขาวิ่งเข้าหา Router หลักโดยตรง<br>ยังไม่รองรับการต่อแบบเรียงต่อกันเป็นทอด ๆ เช่นสำนักงานใหญ่ต่อไปสาขา A แล้วสาขา A ต่อไปสาขา B อีกที เพราะโปรแกรมสร้างเส้นทางให้เฉพาะอุปกรณ์ที่ต่อสายถึงกันโดยตรงเท่านั้น |

## ข้อความที่เด้งขึ้นมาตอนใช้งาน

### เคยเป็นภาษาอังกฤษล้วน

| เดิม | ใหม่ |
|---|---|
| `VLSM Calculated` | คำนวณเรียบร้อยแล้ว |
| `IPv6 Calculated` | คำนวณ IPv6 เรียบร้อยแล้ว |
| `Layout reset` | จัดขนาดหน้าจอกลับเป็นค่าเริ่มต้นแล้ว |
| `Ready — กดปุ่ม EXAMPLE เพื่อโหลดข้อมูลตัวอย่าง` | พร้อมใช้งาน ถ้ายังไม่รู้จะเริ่มยังไง ลองกดปุ่ม EXAMPLE เพื่อโหลดตัวอย่างดูก่อน |
| `Cleared — กด EXAMPLE เพื่อเริ่มต้น` | ล้างข้อมูลหมดแล้ว กดปุ่ม EXAMPLE เพื่อเริ่มจากตัวอย่าง หรือเพิ่มแผนกเองได้เลย |
| `Loaded: <ชื่อ> — 6 depts — 10.0.0.0/22` | โหลดตัวอย่าง `<ชื่อ>` แล้ว มี 6 แผนก ใช้เลขตั้งต้น 10.0.0.0/22 |
| `Loaded project — 8 depts — …` | เปิดไฟล์งานแล้ว มี 8 แผนก ใช้เลขตั้งต้น … |

### เคยสั้นห้วนจนไม่รู้ว่าต้องทำอะไรต่อ

| เดิม | ใหม่ |
|---|---|
| `Hosts >= 1` | จำนวนเครื่องต้องเป็นตัวเลขตั้งแต่ 1 ขึ้นไป |
| `CIDR ต้อง 8-30` | ตัวเลขหลังเครื่องหมาย / ต้องอยู่ระหว่าง 8 ถึง 30 |
| `Base Prefix ต้อง 1-127` | ความยาว Prefix ของ IPv6 ต้องอยู่ระหว่าง 1 ถึง 127 |
| `IP ไม่ถูกต้อง` | รูปแบบเลข IP ไม่ถูกต้อง ต้องเป็นตัวเลขสี่ชุดคั่นด้วยจุด |
| `ระบุชื่อแผนก` | ยังไม่ได้ตั้งชื่อแผนก |
| `Subnet เต็มแล้ว ไม่เหลือ IP ให้แนะนำ` | IP ในแผนกนี้ถูกใช้หมดแล้ว ไม่เหลือเบอร์ว่างให้แนะนำ |
| `ต้องเชื่อมกับ Switch ก่อนถึงจะแนะนำ IP ได้` | ต้องลากสายเชื่อมอุปกรณ์นี้เข้ากับ Switch ของแผนกก่อน โปรแกรมถึงจะรู้ว่าควรแนะนำ IP เบอร์ไหน |

| ลบอุปกรณ์แล้ว — กด Ctrl+Z เพื่อย้อนกลับ | ลบอุปกรณ์แล้ว ถ้าลบผิดกด Ctrl+Z เพื่อเอากลับคืนได้ |

| ปรับ Base เป็น /24 — เล็กที่สุดที่ยังจองครบทุกแผนก | ปรับเลขตั้งต้นเป็น /24 ให้แล้ว ซึ่งเป็นขนาดเล็กที่สุดที่ยังพอใช้ครบทุกแผนก |
| วาง Router สาขาแล้ว — ยังใช้ไม่ได้จนกว่าจะกด Connect ลากไปหา Router-01 | วาง Router ของสาขาแล้ว แต่ยังใช้งานไม่ได้ ต้องกดปุ่ม Connect แล้วลากสายไปเชื่อมกับ Router-01 ก่อน |

## แผงสรุปการใช้พื้นที่

| เดิม | ใหม่ |
|---|---|
| การใช้พื้นที่ใน 10.0.0.0/22 · 1,024 addresses | IP ในช่วง 10.0.0.0/22 ถูกใช้ไปกับอะไรบ้าง · มีทั้งหมด 1,024 เบอร์ |
| ใช้จริง | ใช้งานจริง |
| เสียจากการปัด | เสียเพราะปัดขนาด |
| สำรองเผื่อโต | เหลือเผื่อขยาย |
| "เสียจากการปัด" เลี่ยงไม่ได้ เพราะ subnet ต้องมีขนาดเป็นกำลังสองเสมอ — ต่อให้เลือก Base พอดีเป๊ะ ก็ใช้ได้สูงสุด 73% · "สำรองเผื่อโต" ไม่ใช่ความสูญเปล่า | ส่วนที่เสียไปเพราะปัดขนาดขึ้นเป็นเรื่องปกติ หลีกเลี่ยงไม่ได้ เพราะขนาดของแต่ละกลุ่มต้องเป็น 2, 4, 8, 16 ไล่ขึ้นไปเรื่อย ๆ เท่านั้น ต่อให้เลือกเลขตั้งต้นได้พอดีที่สุดแล้ว ก็ยังใช้ได้สูงสุดแค่ 73% อยู่ดี<br>ส่วนที่เหลือไว้เผื่อขยายไม่ถือว่าเสียเปล่า เพราะเป็นพื้นที่ที่กันไว้ให้เพิ่มเครื่องได้ในอนาคต |
| ถ้าย่อ Base เป็น /24 สัดส่วนใช้จริงจะขึ้นเป็น 73% · ปุ่ม "ปรับให้" | ถ้าเปลี่ยนเลขตั้งต้นเป็น /24 สัดส่วนที่ได้ใช้จริงจะเพิ่มเป็น 73% · ปุ่ม "เปลี่ยนให้เลย" |

## สิ่งที่ **ไม่ได้** แก้ และเหตุผล

- **คอมเมนต์ในโค้ด** ยังใช้ขีดยาวและศัพท์เทคนิคเต็มที่ เพราะเขียนไว้ให้คนที่มาแก้โค้ดอ่าน ไม่ใช่ผู้ใช้ทั่วไป
- **ชื่อปุ่มบนแถบเครื่องมือ** (EXAMPLE, EXPORT, LIBRARY, SAVE, LOAD, CLEAR, RESET) คงไว้ เพราะเป็นชื่อเฉพาะที่คู่มือกับข้อความเตือนอ้างถึงตรง ๆ ถ้าเปลี่ยนต้องไล่แก้ทุกที่ที่พูดถึงมัน
- **ศัพท์ในตาราง IP** (Network, Broadcast, Usable Range, Subnet Mask, CIDR, Wildcard) คงไว้ เพราะเป็นหัวข้อมาตรฐานที่ตรงกับที่เรียนในวิชาและตรงกับเอกสารของ Cisco

## ถ้าจะแก้เพิ่มเอง

ข้อความที่เด้งขึ้นมาตอนใช้งานทั้งหมดอยู่ในไฟล์ `js/*.js` ค้นด้วยคำว่า `showToast(`
ส่วนคู่มืออยู่ใน `index.html` ค้นด้วย `onboard-step-desc`

มีสคริปต์ `tools/rewrite-copy.js` เก็บคู่ "ข้อความเดิม → ข้อความใหม่" ของรอบนี้ไว้ทั้งหมด
เปิดดูได้ว่ารอบนี้เปลี่ยนอะไรไปบ้าง แต่ถ้าจะแก้เพิ่มในอนาคต แก้ในไฟล์ต้นทางโดยตรงจะตรงไปตรงมากว่า
