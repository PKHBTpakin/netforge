# คำศัพท์กลางของ NetForge

เอกสารตัดสินคำ ปรับปรุง 25 ส.ค. 2569

เอกสารนี้เป็น **ข้อตัดสิน** ไม่ใช่ข้อเสนอ ทุกครั้งที่จะเขียนข้อความใหม่ที่ผู้ใช้เห็น
ให้เปิดไฟล์นี้ก่อน ถ้าคำที่จะใช้ไม่ตรงกับที่ระบุไว้ แปลว่าใช้ผิด ไม่ใช่ว่าเอกสารล้าสมัย

ถ้าจะเปลี่ยนคำใดคำหนึ่งในอนาคต ให้แก้ที่ไฟล์นี้ก่อน แล้วค่อยไล่แก้โค้ดตาม
ห้ามแก้โค้ดโดยไม่แก้ไฟล์นี้ เพราะจะกลับไปสู่สภาพเดิมที่คำเดียวมีหลายชื่ออีก

**ขอบเขต:** ใช้กับข้อความที่ผู้ใช้เห็นเท่านั้น คือ `index.html` และ string ในไฟล์ `js/*.js`
ไม่ใช้กับคอมเมนต์ในโค้ด ซึ่งเขียนไว้ให้คนที่มาแก้โค้ดอ่าน จะใช้ศัพท์เทคนิคเต็มที่ก็ได้

## หลักที่ใช้ตัดสิน — เส้นแบ่ง 3 เส้น

เวลาเจอคำใหม่ที่ยังไม่มีในเอกสารนี้ ให้ถามสามคำถามนี้ตามลำดับ

### เส้นที่ 1 — ผู้ใช้ต้องไปเจอคำนี้ซ้ำนอกแอปหรือไม่

ถ้าเขาต้องพิมพ์มันใน Packet Tracer เห็นมันในข้อสอบ หรือเสิร์ชหาต่อ
→ **คงภาษาอังกฤษเสมอ ห้ามแปล**

ถ้าแปล เช่นเปลี่ยน Broadcast Address เป็น "หมายเลขกระจายสัญญาณ"
ผู้ใช้จะอ่านข้อสอบไม่ออกและค้นหาต่อไม่เจอ เท่ากับทำร้ายเขา ไม่ได้ช่วย

### เส้นที่ 2 — คำนี้เป็นศัพท์วิชาเครือข่าย หรือแค่ศัพท์หน้าจอ

ถ้าเป็นแค่ชิ้นส่วนของโปรแกรม ไม่ใช่ความรู้เครือข่าย
→ **ต้องเป็นภาษาไทยเสมอ**

Canvas, Node, Sidebar, Layout, Panel, Block, Light Mode, Dark Mode อยู่ในกลุ่มนี้ทั้งหมด
ผู้ใช้ไม่ได้ประโยชน์อะไรจากการรู้ศัพท์อังกฤษของคำพวกนี้ มีแต่จะงง

### เส้นที่ 3 — แปลแล้วความหมายเพี้ยนหรือไม่

ถ้าเพี้ยน → **คงอังกฤษไว้ แต่ใส่คำอธิบายไทยในวงเล็บเฉพาะครั้งแรกที่โผล่**
ครั้งต่อ ๆ ไปใช้คำอังกฤษเปล่า ๆ

อธิบายทุกครั้งจะทำให้ข้อความยาวจนไม่มีใครอ่าน ไม่อธิบายเลยคนใหม่ก็ไม่รอด
อธิบายครั้งเดียวคือจุดพอดี

## กฎเหล็ก: ชื่อในข้อความต้องตรงกับป้ายที่ตาเห็นบนหน้าจอ

นี่คือกฎที่ชนะกฎอื่นทั้งหมดเมื่อขัดกัน

ถ้าช่องกรอกบนหน้าจอเขียนว่า `Base` แล้วข้อความแจ้งเตือนเขียนว่า "ปรับเลขตั้งต้นให้แล้ว"
ผู้ใช้จะกวาดตาหาคำว่า "เลขตั้งต้น" บนหน้าจอแล้วไม่เจอ ต่อให้คำไทยนั้นอ่านเข้าใจง่ายกว่าก็ตาม

เพราะฉะนั้นคำที่ปรากฏบนป้าย ปุ่ม และหัวตาราง คือคำที่ข้อความทุกที่ต้องใช้ตาม

## ตารางที่ 1 — ศัพท์วิชาที่ห้ามแปล

คำเหล่านี้คงภาษาอังกฤษเสมอ ทุกที่ ทุกบริบท ห้ามหาคำไทยมาแทน

| กลุ่ม | คำ |
|---|---|
| อุปกรณ์ | Router · Switch · PC · Server |
| การแบ่ง IP | subnet · VLSM · CIDR · Prefix · Subnet Mask · Wildcard Mask |
| หมายเลขเฉพาะ | Network Address · Broadcast Address · Gateway |
| เลเยอร์ 2 | VLAN · Trunk · Access Port |
| บริการ | DHCP · SLAAC |
| WAN | Serial · DCE · DTE · clock rate |
| อื่น ๆ | CLI · Topology (ดูข้อจำกัดในตารางที่ 2) |

### กฎตัวพิมพ์ของคำเหล่านี้

- **อยู่ในประโยคภาษาไทย** ใช้ตัวเล็กตามที่คำนั้นเขียนจริงในเอกสาร Cisco
  เช่น `subnet` `clock rate`
- **เป็นหัวตาราง หรือชื่อเฉพาะที่มีสองคำขึ้นไป** ใช้ตัวใหญ่ขึ้นต้นแต่ละคำ
  เช่น `Subnet Mask` `Network Address` `Clock Rate` (ในหัวตาราง)

กฎนี้โค้ดปัจจุบันทำถูกอยู่แล้วทุกจุด เขียนไว้เพื่อไม่ให้หลุดในอนาคต

### ห้าม CSS แปลงตัวพิมพ์ของคำเหล่านี้

โค้ดเขียนถูก ไม่ได้แปลว่าหน้าจอแสดงถูก `text-transform: uppercase` ใน CSS
จะแปลง `IPv4` เป็น `IPV4` ตอนแสดงผล ทั้งที่ในไฟล์เขียนไว้ถูกต้องแล้ว

`IPV4` ไม่ใช่วิธีเขียนที่ถูกต้อง มาตรฐานคือ `IPv4` เสมอ v ตัวเล็ก
เป็นคำที่ผู้ใช้ต้องเจอในข้อสอบและเอกสาร Cisco การเขียนผิดบนหน้าจอ
ทำให้เว็บเสียความน่าเชื่อถือทันทีในสายตาคนที่รู้จริง

คลาสใน `css/style.css` ที่มี `text-transform: uppercase` มี 4 ตัว

| คลาส | บรรทัด | มีศัพท์ตัวพิมพ์ผสมไหม |
|---|---|---|
| `.btn-neon` | 182 | **มี** ปุ่ม `IPv4` แสดงเป็น `IPV4` |
| `.section-label` | 220 | **มี** `SUBNET INFO (IPv4)` และ `(IPv6)` แสดงเป็น `(IPV4)` `(IPV6)` |
| `.btn-example` | 211 | ไม่มี |
| `.tab-btn` | 233 | ไม่มี |

**ทำไมปุ่ม IPv4 กับ IPv6 ถึงสะกดต่างกันบนหน้าจอ** ปุ่มซ้ายใช้ `.btn-neon` ซึ่งมี uppercase
ปุ่มขวาใช้ `.btn-cyber` ซึ่งไม่มี ผลคือปุ่มคู่กันที่ทำหน้าที่เดียวกัน สะกดคนละแบบ

**วิธีแก้ที่เลือก** เพิ่มคลาสช่วยตัวเดียวแล้วแปะเฉพาะจุดที่มีปัญหา
ไม่ไปแตะ `text-transform` ของคลาสเดิม เพราะปุ่มอื่นที่ใช้ `.btn-neon` ยังต้องเป็นตัวใหญ่อยู่

```css
.keep-case { text-transform: none; }
```

จุดที่ต้องแปะมี 3 จุด: ปุ่ม `IPv4` และหัวข้อ `SUBNET INFO` ทั้งสองอัน

หมายเหตุ `.text-muted` `.text-label` `.text-subtle` กำหนดแค่สี ไม่ได้แปลงตัวพิมพ์
ป้ายอย่าง `Network` `Broadcast` `Subnet Size` จึงแสดงถูกต้องอยู่แล้ว

## ตารางที่ 2 — คำตัดสิน

ช่อง "ห้ามใช้" คือคำที่เคยมีอยู่ในโค้ดและต้องถูกกำจัดออกให้หมด

### 2.1 Base

| | |
|---|---|
| **ใช้** | `Base` |
| **ครั้งแรกในคู่มือ** | `Base (ช่วง IP ตั้งต้น)` |
| **ห้ามใช้** | เลขตั้งต้น · ค่าตั้งต้น · IP ตั้งต้น · Base IP (ยกเว้นเป็นป้ายช่องกรอก) |

เหตุผลที่ไม่ใช้ "เลขตั้งต้น": ป้ายช่องกรอกบนหน้าจอเขียนว่า Base
และคำว่า "เลข" ยังคลาดเคลื่อน เพราะ Base ไม่ใช่ตัวเลขตัวเดียว แต่เป็นก้อน IP ทั้งก้อนที่จะเอามาแบ่ง
คำอธิบายในวงเล็บจึงต้องเป็น "ช่วง IP ตั้งต้น" ไม่ใช่ "เลขตั้งต้น"

ฝั่ง IPv6 ใช้ `Base IPv6` เป็นชื่อเต็ม และห้ามใช้คำว่า `Block` ลอย ๆ
ถ้าต้องพูดถึงก้อน IPv6 ให้เขียนว่า "ก้อน IPv6 ตั้งต้น"

### 2.2 Host

คำนี้มีสองความหมายที่ต่างกันจริง ห้ามใช้คำไทยคำเดียวคลุมทั้งคู่

| ที่ปรากฏ | ความหมาย | คำที่ใช้ |
|---|---|---|
| ป้ายช่องกรอกตอนเพิ่มแผนก | จำนวนเครื่องที่แผนกต้องใช้ | ป้ายช่อง `Hosts` |
| ในประโยคภาษาไทย | จำนวนเครื่องที่แผนกต้องใช้ | "จำนวนเครื่อง" |
| หัวตาราง IP และคู่มือ Lab | จำนวน IP ที่ตั้งให้เครื่องได้ | `Usable Host` |

**ห้ามเขียน "จำนวนเครื่อง" แทน Usable Host** เพราะมันคือจำนวน IP ไม่ใช่จำนวนเครื่อง

#### ป้ายช่องกรอกในกล่อง ADD DEPARTMENT

ช่องสองช่องนี้วางคู่กันในแถวเดียว ห่างกันไม่กี่พิกเซล ป้ายจึงต้องเป็นภาษาเดียวกัน

| ช่อง | ป้ายที่ใช้ |
|---|---|
| ซ้าย | `Department` |
| ขวา | `Hosts` |

**ห้ามใช้ "ชื่อแผนก" เป็นป้ายช่องนี้** เพราะจะกลายเป็นไทยคู่กับอังกฤษในแถวเดียวกัน

เหตุผลที่เลือกอังกฤษทั้งคู่ ไม่ใช่ไทยทั้งคู่

1. หัวตาราง IP TABLE เขียนว่า `Department` กับ `Hosts` อยู่แล้ว ผู้ใช้กรอกช่องไหน
   ก็เห็นคำเดียวกันนั้นโผล่ในตารางผลลัพธ์ทันที
2. หัวกล่องเขียนว่า `ADD DEPARTMENT` อยู่แล้ว
3. การ์ดแผนกในแถบด้านซ้ายขึ้นว่า `Hosts: 50` อยู่แล้ว

ส่วนในประโยคภาษาไทยยังใช้ "จำนวนเครื่อง" ตามเดิม เช่นข้อความแจ้งเตือน
"จำนวนเครื่องต้องเป็นตัวเลขตั้งแต่ 1 ขึ้นไป"

### 2.3 อุปกรณ์บนผัง

| | |
|---|---|
| **ใช้** | อุปกรณ์ |
| **ห้ามใช้** | Node · โหนด |

หัวข้อแผงด้านขวาใช้ **"รายละเอียดอุปกรณ์"** ไม่ใช่ `NODE DETAILS`

### 2.4 ผังเครือข่าย

| | |
|---|---|
| **ใช้** | "ผังเครือข่าย" ครั้งแรก จากนั้นใช้ "ผัง" เปล่า ๆ |
| **ห้ามใช้** | Canvas · Topology Canvas · พื้นที่วาด |

คำว่า `Topology` **ยังใช้ได้ แต่เฉพาะตอนพูดถึงรูปแบบการเชื่อมต่อ** เช่นการต่อแบบดาว
ซึ่งเป็นศัพท์วิชาที่มีในข้อสอบ ใช้ได้ในหน้ากฎการคำนวณและคู่มือเท่านั้น
ห้ามใช้เรียกพื้นที่วาดบนหน้าจอ

### 2.5 โปรเจกต์และคลัง

| | |
|---|---|
| **ชิ้นงานหนึ่งชิ้น** | โปรเจกต์ |
| **ที่เก็บ** | คลังโปรเจกต์ |
| **ไฟล์ `.json`** | ไฟล์โปรเจกต์ |
| **ห้ามใช้** | งาน · ชิ้นงาน · คลังเก็บงาน · คลังงาน · เก็บงานไว้หลายชิ้น |

เหตุผลที่ไม่ใช้คำว่า "งาน": กำกวมเกินไปในภาษาไทย
ประโยคอย่าง "บันทึกงานแล้ว" อาจหมายถึงบันทึกอะไรก็ได้
ส่วน "โปรเจกต์" ชี้เฉพาะเจาะจงว่าหมายถึงไฟล์ชิ้นนั้น และเป็นคำที่นักศึกษาสายไอทีคุ้นอยู่แล้ว

**ข้อยกเว้นเดียว** คือคำว่า "งาน" ที่ไม่ได้หมายถึงไฟล์โปรเจกต์ เช่น "ใช้งาน" "ทำงาน" "งานจริง"
คำเหล่านี้ใช้ได้ตามปกติ

| **ป้ายบนปุ่ม** | แปลน (ย่อได้ เพราะปุ่มมีพื้นที่จำกัด) |

คำว่า "พื้นหลัง" ห้ามใช้เด็ดขาด เพราะผู้ใช้จะเข้าใจว่าเป็นสีพื้นหลังของธีมสว่าง/มืด

## กฎรูปประโยคของข้อความแจ้งเตือน

ข้อความแจ้งเตือนหนึ่งอันต้องตอบสองคำถามให้ครบ

1. **เกิดอะไรขึ้น**
2. **ต้องทำอะไรต่อ**

ถ้าตอบได้ข้อเดียว แปลว่ายังเขียนไม่เสร็จ

### แยกให้ชัดระหว่างสองสถานการณ์

**แบบที่ 1 ผู้ใช้กรอกผิดหรือทำผิดขั้นตอน** — บอกวิธีแก้ให้ชัดเจนเป็นรูปธรรม

> จำนวนเครื่องต้องเป็นตัวเลขตั้งแต่ 1 ขึ้นไป
>
> ต้องลากสายเชื่อมอุปกรณ์นี้เข้ากับ Switch ของแผนกก่อน โปรแกรมถึงจะรู้ว่าควรแนะนำ IP หมายเลขไหน

**แบบที่ 2 โปรแกรมทำงานผิดพลาดเอง** (พวกที่อยู่ใน `catch`) — ต้องบอกว่าไม่ใช่ความผิดผู้ใช้ และให้ทางออกที่ทำได้จริง

> ❌ คำนวณ IPv6 ไม่สำเร็จ
>
> ✅ คำนวณ IPv6 ไม่สำเร็จ ลองกดคำนวณอีกครั้ง ถ้ายังไม่ได้ให้กดปุ่ม SAVE เก็บโปรเจกต์ไว้ก่อนแล้วรีเฟรชหน้าเว็บ

ปัจจุบันมีข้อความรูปแบบ `"<ทำอะไร> ไม่สำเร็จ"` อยู่ประมาณ 47 จุด
ซึ่งปนกันทั้งสองแบบและใช้สำนวนเดียวกันหมด ทำให้ผู้ใช้แยกไม่ออกว่าตัวเองทำผิดหรือโปรแกรมพัง

### คำต้องห้ามด้านน้ำเสียง

| ห้ามใช้ | ใช้แทน | เหตุผล |
|---|---|---|

| กรุณา | ประโยคบอกเล่าตรง ๆ | ทั้งแอปใช้แค่ 3 จุด ทำให้ 3 จุดนั้นดูแปลกแยกจากที่เหลือ |

## กฎของปุ่มและหัวข้อ

| ประเภท | ภาษา | รายการ |
|---|---|---|
| ปุ่มแถบเครื่องมือหลัก ที่คู่มืออ้างถึงเป็นชื่อเฉพาะ | อังกฤษตัวใหญ่ | EXAMPLE · EXPORT · LIBRARY · SAVE · LOAD · CLEAR · RESET · HELP |
| ปุ่มคำสั่งบนผัง | อังกฤษ | PC · Server · Router · Connect |
| ปุ่มย่อยในกล่องเครื่องมือ | ไทย | คำนวณ · เพิ่ม · สรุปเส้นทาง · คัดลอก · ขยาย |

**เหตุผลที่ปุ่มกลุ่มแรกคงอังกฤษ:** คู่มือและข้อความแจ้งเตือนอ้างถึงมันตรง ๆ หลายสิบจุด
เช่น "กดปุ่ม EXAMPLE เพื่อโหลดตัวอย่าง" ถ้าเปลี่ยนชื่อปุ่มต้องไล่แก้ทุกจุดที่พูดถึงมัน

**สิ่งที่ต้องเปลี่ยนตามกฎนี้**

| ปัจจุบัน | เปลี่ยนเป็น |
|---|---|
| `Calc` (ในกล่อง Wildcard Mask) | คำนวณ |
| `Add` (ในกล่อง Route Summary) | เพิ่ม |
| `Summarize` | สรุปเส้นทาง |
| `โหมด PT` | ตัดคอมเมนต์ไทย |

`Calculate` ของ VLSM คงไว้ เพราะคู่มืออ้างถึงในฐานะชื่อเฉพาะ ("ปุ่มรูปไม้กายสิทธิ์ข้างปุ่ม Calculate")

ปุ่ม `โหมด PT` ต้องเปลี่ยนเพราะ PT เป็นตัวย่อที่ผู้ใช้ใหม่ไม่มีทางเดาถูก
ชื่อใหม่บอกสิ่งที่ปุ่มทำจริง ส่วนคำว่า Packet Tracer ให้ไปอยู่ใน tooltip

## กฎเครื่องหมายวรรคตอน

| ห้ามใช้ | ใช้แทน |
|---|---|
| `—` ขีดยาวคั่นกลางประโยค | ขึ้นประโยคใหม่ หรือใช้คำเชื่อม |
| `·` จุดกลางคั่นรายการ | ขึ้นบรรทัดใหม่ หรือใช้คำว่า "และ" |
| `–` ขีดกลางคั่นช่วงตัวเลข | คำว่า "ถึง" |

ตัวอย่างที่ยังเหลือใน `index.html`

> ใช้ในองค์กร: 10.x · 172.16-31.x · 192.168.x

และใน `js/ui.js` ที่แสดงช่วง IP ของ subnet

> (10.0.0.1 – 10.0.0.30) → (10.0.0.1 ถึง 10.0.0.30)

## จุดที่รู้แล้วว่าเขียนผิด ต้องแก้แน่นอน

### `index.html` บรรทัด 312 — คำผิดใน aria-label

```
aria-label="Base IPv6 เช่น 2001:db8 ซีเมิคโคลอนคู่"
```

ผิดสองชั้น

1. "ซีเมิคโคลอน" สะกดผิด ที่ถูกคือ "เซมิโคลอน"
2. ใช้คำผิดตั้งแต่ต้น เครื่องหมาย `:` คือ **โคลอน** ส่วนเซมิโคลอนคือ `;` ซึ่งไม่เกี่ยวกับ IPv6 เลย

ข้อความนี้เป็นข้อความสำหรับโปรแกรมอ่านหน้าจอ ผู้ใช้ที่ตาบอดจะได้ยินคำที่ผิด

แก้เป็น `Base IPv6 เช่น 2001:db8 ตามด้วยโคลอนสองตัว`

## ป้ายอังกฤษล้วนในแผงรายละเอียดอุปกรณ์ — รอตัดสินในรอบที่ 5

### ข้อบกพร่องของการสำรวจครั้งแรก ต้องทำใหม่ก่อนเริ่มรอบที่ 5

การสำรวจข้อความรอบแรกกรองเฉพาะบรรทัดที่ **มีอักษรไทย**
ป้ายที่เป็นภาษาอังกฤษล้วนจึงหลุดตะแกรงไปทั้งหมด รวมถึงป้ายทุกอันในแผงด้านขวา
ก่อนเริ่มรอบที่ 5 ต้องสำรวจใหม่โดยไม่กรองภาษา

### รายการป้ายที่พบ

| ป้าย | เป็นศัพท์วิชาไหม | แนวทาง |
|---|---|---|
| `VLAN ID` | ใช่ | คงไว้ |
| `SUBNET INFO (IPv4)` / `(IPv6)` | ใช่ | คงไว้ แต่ต้องแก้ปัญหา uppercase |
| `Network` `Broadcast` `Usable` `Mask` `Wildcard` | ใช่ | คงไว้ ตรงกับหัวตาราง IP TABLE |
| `SUBNET MASK` `BASE NETWORK` `TOTAL SUBNETS` | ใช่ | คงไว้ |
| `DEPARTMENT NAME` | ไม่เชิง | ตัดสินในรอบที่ 5 |
| `REQUIRED HOSTS` | ครึ่งเดียว Hosts เป็นศัพท์วิชา แต่ REQUIRED ไม่ใช่ | ตัดสินในรอบที่ 5 |
| `CONNECTED DEPARTMENT` | ไม่ใช่ | ตัดสินในรอบที่ 5 |
| `TRUNK TO` | ครึ่งเดียว Trunk เป็นศัพท์วิชา แต่ TO ไม่ใช่ | ตัดสินในรอบที่ 5 |
| `Subnet Size` / `64 addresses` | ครึ่งเดียว | ตัดสินในรอบที่ 5 |
| `Total Addresses` | ไม่ใช่ | ตัดสินในรอบที่ 5 |

### ความไม่สม่ำเสมอที่พบระหว่างทาง

`js/ui.js` บรรทัด 570 เขียน `CONNECTED DEPARTMENTS` มี s
แต่บรรทัด 591 เขียน `CONNECTED DEPARTMENT` ไม่มี s
เป็นแผงคนละแบบ (Router กับ Switch) แต่ควรใช้รูปเดียวกัน
